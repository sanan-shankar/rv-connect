### T4a-02 — In Chronological order a year holding more than 600 photographs is silently cut to 600 in the river while the rail still counts all of them
- Severity: Medium
- Confidence: certain on the mechanism; the data state does not exist yet (the largest year today is 2022 with 465 class photographs), but the class archive already puts 440-465 into single years from one contributor, and the design is for classes of 30-40 members at 1,000 each.

- Taxonomy: 6j (`findMany` bound that silently truncates), 6a boundary value (600, 601), 6h pagination "page-size+1"
- Expected: the river shows every approved photograph of a year; `bands` and the river agree ("the rail's rows and the river's chapters can never disagree about which year a photograph is in", `actions.ts` comment above the groupBy).
- Actual: `loadBand(key)` returns the first 600 of the year in `takenKey DESC, id DESC` order. The client then `reshapeBand`s the shape index to those 600, so the year's box shrinks to fit them and is drawn complete-looking. Photographs 601+ of that year are never fetched by any path: the cursor loader is disabled whenever boxes exist (`collection-client.tsx:880-883`, "if (boxesRef.current.length > 0) return;"), and `needBand` will not re-ask a key it already holds. - Why: `take: 600` with no continuation; the client treats the returned set as the whole year. Trigger: any (scope, bucket, search) view whose single year exceeds 600 rows.
- Proof: read-only today: `SELECT "photoYear", count(*) FROM "Photo" WHERE scope='class' AND approved AND NOT "isHidden" GROUP BY 1 ORDER BY 2 DESC` (465 max). Argue-only for the failure until a year passes 600. A unit test is the honest proof: `reshapeBand` with a run of 700 in the index and 600 photos handed in produces an index of 600 and `holdsBand` true.
- Fix direction: either make `loadBand` page within a year (a second call with a `takenKey,id` cursor when `rows.length === 600`, and the client keeps asking until the count matches the index), or raise the guard and make the shortfall LOUD: if `data.photos.length < box.count`, keep asking rather than reshaping. `reshapeBand` should only reshape when the server said the year is complete.
- Gate: a `river-geometry.test.mjs` case that a partial band is never adopted as complete; an `actions`-level test that `loadBand` continues past 600.
- Known-related: the 2026-09-09/12 river work (owner: "when I upload something to 2014, all the photos of that year disappear") is why `reshapeBand` adopts whatever arrives; this is that fix's blind spot.

## Inputs for the live naughty-strings pass

- **Caption** (contribute room, edit dialog, review room; `photoSchema.caption`: `.trim().max(300)`) — lands in `Photo.caption`; rendered by React in the viewer and the rail (`headingTextWidth` measures it), as `alt`, in the page `<title>` through `generateMetadata` (cut at 70), and into the download filename through `collectionSaveName` (`photo-save-name.ts` replaces control and reserved characters, collapses dots, strips a leading dot, caps at 72). Classes that matter: NUL and other C0 controls (Postgres refuses `\0` -> the action throws -> `ACTION_FAILED`; other controls store fine and are replaced in the filename), RTL override and ZWJ sequences (300 is a code-unit cap, so a 150-emoji ZWJ string is accepted and wraps oddly in the rail's 260px line), `<script>`/HTML (React-escaped; the title path goes through Next's metadata escaping), a 300-character run of `.` (filename collapses to one dot then strips it). Live longest caption today: 47 characters.
- **Decline reason** (admin, `declinePhoto` `reason`, sliced to 300 after trim) — embedded verbatim inside a notification sentence with quotes around it; NUL -> Postgres error after the photograph is already erased (see Leads L6).
- **Search `q`** (`riverFiltersFrom`: slice 100 + trim; the action: slice 100 + trim; `escapeLike`) — `%`, `_`, `\` escaped; a term ending in a lone backslash at the cap is handled by clamp-before-escape; unicode passes to ILIKE (case folding is Postgres's). Payload classes: 100 `%`s (escaped, harmless), combining-character-heavy strings (no crash), the 20KB string (clamped).
- **`bucket`, `order`, `band`, `scope`, `cursor` as action arguments** — unvalidated but bounded: `bucket` through `escapeLike`; `order` unknown -> "newest"; `band` non-year/non-era -> `null` boundary; `scope` not "valley" -> the caller's own class; `cursor` via `decodeCursor` (NaN, negative, > 10,000 offset refused). Payload classes: `bucket: "%"`, `band: "9999"`, `cursor: "off~1e12"`, `cursor: "NaN~x"`.
- **`presign` body** — `contentType` (lowercased, table lookup), `filename` (only `\.([a-z0-9]+)$` is read), `bytes` (must be a finite positive number <= 20MB; `"20"` as a string is refused by `typeof`). Payload classes: `bytes: 1e308`, `bytes: -1`, `filename: "a.JPG\u0000.exe"` (extension regex reads `exe`? no: `$` anchors after `exe`, and `exe` is not in the table -> refused).
- **`input.key` on `contributePhotoDirect`** — regex `^(staging|collection)\/[a-z0-9]+\/\d{4}\/\d{2}\/[a-z0-9]+-o\.(jpg|jpeg|png|webp|gif)$` plus `keyBelongsTo`; a key for another member's prefix is "Bad upload reference" and is NOT deleted (correct: not ours to aim at).
- **`import-album.mjs --captions` TSV** — a caption over 300 or empty aborts before any encode; a tab inside a caption is a column split; the file name is matched by basename only, so two folders with the same file name share a line (only with no `--folder`).
