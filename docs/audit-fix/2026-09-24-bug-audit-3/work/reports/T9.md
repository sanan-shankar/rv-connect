## Findings

Grounding fact for every finding below (verified in `node_modules`, motion 12.38.0 / motion-dom 12.38.0,
React 19.2.4, Next 16.3.3): `JSAnimation.stop()` and `.cancel()` both call `teardown()`, which never
calls `notifyFinished()` (`motion-dom/dist/es/animation/JSAnimation.mjs:44-55, 345-363`), and
`MotionValue.start()` begins with `this.stop()` on the value's current animation
(`motion-dom/dist/es/value/index.mjs:260-287`). A `GroupAnimation`'s `finished` is
`Promise.all(children.finished)` (`GroupAnimation.mjs:7-9`). So an animation that is stopped OR
superseded by a later write to the same element+property never settles, and neither does any group
it belongs to. The rig's own comments state this (hoopoe.tsx:249-251, 700-706, 857-861, 1056-1066); it
is true of the installed version.
