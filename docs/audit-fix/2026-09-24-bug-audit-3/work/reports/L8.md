- **Streamed responses are exempt from the 4.5 MB response cap, and the two big responses stream.** "streaming functions ... don't have this limit" (vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions [2025-11-10]); `/api/photo/download` pipes sharp into `Readable.toWeb` (`route.ts:83-97`, its comment's claim is right), `/api/account/export` writes a `ReadableStream` page by page (`route.ts:301`). Every path that does send bytes to a function shrinks first, pinned by `upload-size-rule.test.mjs:24-45` (the only residue is L8-03's narrow band).
- **R2's one-write-per-second-per-key limit cannot be met by the app's own writes except one.** Every `putImage`/`presignImagePut` key carries a fresh `createId()` (`api/upload/route.ts:125,132`, `finalize/route.ts:131`, `collection/actions.ts:240,263,537-539`, `settings/actions.ts:109,118`, `collection-intake.ts:127-129`, `presign/route.ts:99-103`, `audio/route.ts:79`), so rapid avatar re-uploads write new keys (the charter's avatar scenario does not arise).
